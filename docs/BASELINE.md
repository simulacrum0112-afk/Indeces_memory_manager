# 基线与集成差异

文档基线：0.13.0；2026-10-03 核对。远端代码与验证证据见 [CHECKPOINT.md](CHECKPOINT.md)，历史版本条目保留当时行为。

本项目最初从新仓库建立，没有导入 Yuki 私有配置或计算科学数据。下表区分保留的参考策略与为知识文档/runtime 新增的实现选择；0.3.0 对已有 Indeces 知识状态的迁移另列于下文。没有修改原 Yuki。预算是工程初值，不是经过真实延迟/相关性实验调优的最优参数。

用户明确决定：使用 `hebbian-mark-graph` 策略；当前回复仅静态检索，0.13.0 经明确批准关闭回复链的 dynamic/shadow 更新。旧动态权重/审计保留，显式低层 dynamic 只用于兼容；动态上线仍待代表性评测与新的用户决定。聊天模型标词关闭；本地 knowledge 文件更新后触发后台被动标词。模型为 GPT-6-Luna。模型认证暂按官方 Responses API，模型请求默认串行，待进一步用户指定可调整。

历史 0.10.0 审计发现 ≤0.9.3 的实际接线仍选择动态有效权重，与当时仅静态的决定不一致；该版把 Runtime 和低层默认检索明确接到静态模式，但当时每轮仍执行字面 shadow 更新。0.13.0 才关闭该更新并使用存储层邻域索引/局部审计；旧轨迹不能追认成静态实验或无 shadow 实验。详见 [架构与调试合同](ARCHITECTURE.md) 和 [存储合同](MEMORY_STORAGE.md)。

参考固定版本：[8769b9ed](https://github.com/Mingyuliu-botaaa/hebbian-mark-graph/tree/8769b9ed0af3531b9fbc09fb6e084d8e7adf724d)。

调用和运行设置：

0.13.0 的派生索引在摄入/归档事务和启动迁移中维护；NPMI 的全局计数依赖仍要求必要的 scope 重算，不能声称摄入仅需局部更新。查询只通过已发布键、邻接与候选 postings 读取局部材料，脏索引拒绝并留给维护路径处理。时间戳与 `lazy_decay` 只作结构预留，没有上线动态衰减或排序。性能曲线、同状态字节对照、摄入/失效验证以交付报告为准；此方法表不等于真实相关性或 5 秒最坏情况证明。[MEMORY_QUERY_SCOPE.md](MEMORY_QUERY_SCOPE.md) 中 0.12.6 测量与待审 lazy shadow 设计属于历史记录，当前合同见 [MEMORY_STORAGE.md](MEMORY_STORAGE.md)。

| 原配置 | 本版配置 | 分类 |
|---|---|---|

0.3.0 知识生命周期的明确变更：

下表描述 0.3.0 当时的回执位置。0.9.2–0.10.0 将普通后台进度放在独立 `knowledge` 窗口和 scratch；0.11.0 改为同一 Console 内的 `knowledge` 面板。0.10.0 补齐标签项数和非空白约束，0.11.0 补齐已有的40字符约束；均不改变块宽或单次模型额度。0.11.0 的显式失败恢复和获批累计资源额度见 [KNOWLEDGE_DIRECTORY.md](KNOWLEDGE_DIRECTORY.md)，不能用历史表格解释当前命令行为。

| 0.2.1 原行为 | 0.3.0 行为 | 分类与影响 |
|---|---|---|
| 默认每 0.5 秒持续扫描；文件更新触发被动标词 | 相同；无更新不调用标词模型 | 保留任务触发与请求规模；没有增加聊天标词或自动入库 |
| 编辑时先撤回旧 head/来源，新版完成前该文档无法检索 | 分开保存待处理版本和已发布版本；有效编辑的 pending/labelling/failed 状态保留旧完整来源，成功后原子切换 | 用户要求的发布语义；回答可能暂时引用旧版，因此回执与检索日志明确来源 ID/digest；没有修改标词内容或 Hebbian 公式 |
| 新记录和 ready 状态在一个事务内发布 | 同一事务也包含旧来源撤回与已发布指针切换 | 一致性设置；失败或回滚不能暴露部分新版，也不能提前丢失旧完整快照 |
| head 按路径保存，未明确区分服务器范围 | 待处理与已发布指针均按 scope/path 保存 | 范围隔离修复；避免 Guild 切换后相同 digest 被误认为本范围已有索引 |
| Console 主要显示 queued/ready/failed 路径，详细信息依赖 scratch | Console 增加开始、逐块进度及完成/失败回执，含版本/来源、digest、当前可检索发布版本；结束回执附已知 usage 与耗时 | 可观察性设置；未知远端 usage 仍在 scratch 明示，不额外发送 Discord 通知或增加模型请求 |
| 删除、清空或无效文件撤回来源；全局文件超限暂停索引 | 相同；在目录检测到状态后执行，不使用旧版回退掩盖删除或无效输入 | 保留撤回边界；归档原文用于审计而非重新取得 active 资格 |
| 原知识表没有显式已发布指针/版本范围归属 | 只接纳旧当前 head 中归属明确、ready 且已有完整 active 记录的版本为发布快照，不重复标词；归属/用量无法确认的旧待处理记录隔离至内容改变 | 明确缓存兼容条件；不恢复已归档或非当前来源，不自动重试未知用量版本 |
| NPMI、η=1、λ=.99、单跳、来源保护；既有独立阶段及知识版本预算 | 相同 | 未改算法公式、模型或 token/时间额度；生命周期验收不代表真实召回质量已验证 |

迁移保留原文、版本、已知 usage、checkpoint 和归档记录。迁移隔离会打印明确回执，不能默默把未验证的旧缓存作为新发布状态使用。只有文件内容的新 digest 才触发隔离版本之后的新任务；单纯重启不承诺恢复或重试。一个旧来源是否兼容依据旧当前 head、完整性、active 状态和可证实范围归属，而非仅凭 `ready` 字样。正在等待模型的回答保留检索时的不可变证据与 trace；撤回/切换发布版本影响后续检索，不是对已开始回复的即时撤销。

未来如进入科研计算，所有 XC、POTCAR、ENCUT、KPOINTS、DFT+U、频率与热力学等科学设置仍必须先提交完整原值→拟改值差异表，并按用户要求取得明确审阅批准；本项目不具备科研作业执行能力。
