# 原始材料目录管理

当前本机入口为 `D:\Indeces\knowledge`，原始 PDF、Markdown、文本都放在这个目录体系内。桌面“Indeces 知识库”快捷方式直接指向它；项目根目录的 `Indeces-Knowledge.cmd` 持续显示只读知识进度，并按实际配置打开目录。Windows Console `knowledge` 打开独立进度窗口，主窗口继续接收命令；其他平台提示在另一终端执行 `python -m indeces knowledge`。`start` 占用主 Console 输入时，可直接另开项目根入口。重新打开 Console 后再启动，以加载新版输出规则；不自动停止或重启已有服务。

可按主题、年份自行建立目录，例如：

```text
knowledge/
  催化/2026/作者_短标题.pdf       # 自动入库候选
  电池/2025/作者_短标题.pdf       # 自动入库候选
  研究笔记.md                    # 自动入库候选
  _staging/                     # 保存尚未选定入库的 raw material
  .indeces/README.md             # 固定管理说明
```

目录入口只创建管理说明和暂存目录，保留已有自定义说明；不自动分类、移动、改名、删除或上传原材料。可读但不可写的安全目录仍显示路径、允许打开，并明确报告说明未准备。转换的 Markdown 单独在 `state_dir/pdf_markdown/`，避免和原 PDF 重复入库；原 PDF 的冻结版本及转换/标词历史在 SQLite 中长期保留。

## 入库与暂存

暂存和管理区以外递归处理 `.pdf`、`.md`、`.markdown`、`.txt`（扩展名不区分大小写）。根级 `_staging/` 和 `.indeces/` 在递归前被排除，暂存区再多资料也不会在每次监听中遍历其正文或子目录。目录链接和 Windows junction 不遍历。普通主题/年份目录仍入库；保留名只针对根级，`催化/_staging/` 属于正常材料目录。

文件链接、reparse point 和非普通文件不入库，也不占候选额度。目录枚举失败时报告 `knowledge_directory_scan_failed`，保留已有发布快照；不把未能读取的目录误判为材料已删除。扫描恢复完成后再处理更新。

目前支持候选上限为 **256**，已同步本地配置；它包括尚未发布、无效或单篇超限的支持格式文件，而非仅成功入库数。其他格式可保存，但尚未支持转换/检索。暂存能力由磁盘容量决定，不代表无限在线索引。

服务 `start` 后才持续检测更新，PDF 本机转换后后台标词，整篇完成才切换已发布版本。普通转换/标词回执不再打印到主 Console；完整事件继续写入 scratch，`knowledge` 窗口显示当前进度、完成或失败状态及可检索版本。每两秒查询一次，状态变化时输出；Ctrl+C 仅退出查看。单次查看可用 `python -m indeces knowledge --once`。目录打开和进度查看均不启动服务、调用模型或修改知识状态。每篇转换/标词与回复的 token、时间预算保持原值，256 仅增加允许的来源数量。

进度来自当前服务器范围的短事务只读 SQLite 快照，不读取原文、PDF 字节或 scratch。显示的已标词块数来自持久 checkpoint；全部块完成仍需已发布指针与 `ready` 状态一致才算发布成功。失败的新版本和可检索旧版本分列。PDF 的排队与转换目前共用一个持久状态，窗口显示“待转换/转换中”，不推测逐页百分比；累计已知耗时也不是实时时钟。停服后仍可查看最后状态，不能据此证明服务在线。显示上限及截断明确报告；数据库缺失或暂不可读不创建、迁移或重放任务。

将暂存文件移到外部的主题目录后才成为候选。反过来，将已入库文件移进根级 `_staging`，会在下一次检测时撤下、归档原来源；物理文件仍保留在暂存区。改名或换路径按旧来源删除、新来源新增处理，不自动合并身份或迁移动态边。文件编辑期间仍沿用上一完整发布版本。

## 超限与保存

第 257 个候选触发现有范围保护：当前服务器范围的所有来源撤下并归档，停止处理，避免未能完成扫描时仍使用陈旧来源。不会静默只取前 256 个。把超量材料留在 `_staging`，维持候选范围不超限。

超限后再降到限额内，需要重新建立来源、转换和标词；不能直接恢复原来的发布指针。历史原文、来源与已知 usage 保留，但重新处理仍可能产生模型费用。不要把这种恢复和正常失败 digest 不自动重试混为一谈。

原始材料和知识版本不受 scratch 的滚动 24 小时清理。`state` 会随 PDF 与版本增长；可在服务已停止时自行备份整个 `knowledge` 与 `state`，以同时保留原文件、知识/图历史及 checkpoint。scratch 是有限保留的运行记录，不替代知识备份。仓库忽略这两类运行数据，提交代码时不要强制添加原始材料。
