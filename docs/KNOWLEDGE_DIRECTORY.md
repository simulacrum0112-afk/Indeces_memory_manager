# 原始材料目录管理

文档基线：0.11.0；2026-10-01 核对。远端代码与验证边界见 [CHECKPOINT.md](CHECKPOINT.md)。

默认原材料入口为 `D:\Indeces\knowledge`，原始 PDF、Markdown、文本都放在这个目录体系内。项目根目录的 `Indeces-Knowledge.cmd`、Console `knowledge` 和 `python -m indeces knowledge` 复用同一 Console 的内部进度面板，并按实际配置打开目录；已有 Console 时切换到该面板，不重启任务或弹出额外交互控制台。其他安装位置以配置路径为准。新服务行为在新进程加载时生效，不自动停止或重启已有服务。

可按主题、年份自行建立目录，例如：

```text
knowledge/
  催化/2026/作者_短标题.pdf       # 自动入库候选
  电池/2025/作者_短标题.pdf       # 自动入库候选
  研究笔记.md                    # 自动入库候选
  _staging/                     # 保存尚未选定入库的 raw material
  .indeces/README.md             # 固定管理说明
```

目录入口只创建管理说明和暂存目录，保留已有自定义说明；不自动分类、移动、改名、删除或上传原材料。可读但不可写的安全目录仍显示路径、允许打开，并明确报告说明未准备。转换的 Markdown 单独在 `state_dir/pdf_markdown/`，避免和原 PDF 重复入库；原 PDF 的冻结版本及转换/标词历史在 SQLite 中长期保留。

## 入库与暂存

暂存和管理区以外递归处理 `.pdf`、`.md`、`.markdown`、`.txt`（扩展名不区分大小写）。根级 `_staging/` 和 `.indeces/` 在递归前被排除，暂存区再多资料也不会在每次监听中遍历其正文或子目录。目录链接和 Windows junction 不遍历。普通主题/年份目录仍入库；保留名只针对根级，`催化/_staging/` 属于正常材料目录。

文件链接、reparse point 和非普通文件不入库，也不占候选额度。目录枚举失败时报告 `knowledge_directory_scan_failed`，保留已有发布快照；不把未能读取的目录误判为材料已删除。扫描恢复完成后再处理更新。

默认支持候选上限为 **256**；已有配置显式值仍按文件读取，0.11.0 未调大默认值。候选包括尚未发布、无效或单篇超限的支持格式文件，而非仅成功入库数。普通文本默认 8192 字节，PDF 默认 16 MiB；文本配置上界为 1 MiB，两条输入路径分别使用 `knowledge.max_file_bytes` 和 `pdf.max_file_bytes`，超限回执记录实际大小、格式、上限与配置键。直接构造和 TOML 加载共用校验。其他格式可保存，但尚未支持转换/检索。暂存能力由磁盘容量决定，不代表无限在线索引。

服务 `start` 后持续检测更新，PDF 本机转换后后台标词，整篇完成才切换已发布版本。普通后台输出保留在 `service`/`logs` 任务面板，完整事件继续写入 scratch；`knowledge` 面板每两秒只读查询，状态变化时显示当前进度、失败与可检索版本。`home`/`back` 切换页面不影响任务；Ctrl+C 或 `stop` 请求停止本 Console 持有的任务。单次查看用 `python -m indeces knowledge --once`。目录打开和进度查看均不启动模型、Discord 或修改知识状态。

进度来自当前服务器范围的短事务只读 SQLite 快照，不读取原文、PDF 字节或 scratch；新增文件审计元数据使验证阶段拒绝也可显示。显示的已标词块数来自持久 checkpoint；全部块完成仍需已发布指针与 `ready` 状态一致才算发布成功。失败的新版本和可检索旧版本分列。PDF 的排队与转换目前共用一个持久状态，不推测逐页百分比；累计已知耗时也不是实时时钟。停服后仍可查看最后状态，不能据此证明服务在线。进度显示额度沿用配置的候选上限（最多 1024），省略明确报告；完整逐篇检查使用 `audit`。数据库缺失或暂不可读不创建、迁移或重放任务。

标词与回复共享一个模型请求槽，等待仍消耗原标词阶段时限；`model_slot_timeout` 不等于供应商失败或已发生成。标签 schema 和本地校验均要求 1–8 个非空词，每词最多 40 字符。每块输入先计量，有效门禁不超过原阶段 cap 与剩余版本输入额度；门禁修复本身不扩额，完整输出 cap 预留与阶段时限不变。单版本累计资源另经明确批准改为196608输入/49152输出/1080秒，旧显式配置仍按原值读取，迁移先备份、持有state租约并等待活动任务结束；400字符块、4096/512/15秒阶段预算和模型不变。收到合法 usage 后，即使标签不合格、取消或审计失败，已知用量仍进入版本累计；没有合法 usage 的已发生成保留未知标记。代码修复不构成对所有历史失败原因的完整证明。

## 审计与显式续跑

Console `audit` 合并完整磁盘清单与当前保存状态，逐篇列出格式、大小、成功/失败/跳过/未完成状态、失败阶段和错误。`stored_error` 是保存的真实失败回执，`validation_error` 是本次只读校验预测，不将二者混同。审计不受图节点、来源详情或进度视图的数量限制，不提取/导出正文，不迁移或调用模型。任务面板保留最近 5000 行、展示最近 100 行，完整一次输出用 `python -m indeces audit --once`。

`retry` 或 `retry "主题/论文.pdf"` 显式恢复当前失败/未完成版本；CLI 使用 `python -m indeces retry --path "主题/论文.pdf"`。ready 版本不重做，已标词块、原文、索引、版本 ID 和累计 input/output/耗时保留。有效旧发布版本继续提供检索，全部缺失块完成后才原子切换。未知远端 usage、额度不足或原文件已经改变的项阻止恢复并说明原因，不以重启重置上限。

本 Console Gateway 活跃时，重试复用原知识事件循环和模型槽；无活动任务时启动失败/未完成项维护线程，不启动 Discord 或新文件发现。维护期间重复 retry 仅复用现有任务，不追加目标。查看和导航不重启任务；`service`/`logs` 查看结果，`stop` 请求停止，清理完成后 `quit`。

`npmi` 区分已索引有效块中的标注出现次数和去重词节点；`audit` 另统计 desired 块的标签，包括尚未发布部分。没有 3000 标注或节点存储上限；节点增长放缓不证明召回改善或收敛。

将暂存文件移到外部的主题目录后才成为候选。反过来，将已入库文件移进根级 `_staging`，会在下一次检测时撤下、归档原来源；物理文件仍保留在暂存区。改名或换路径按旧来源删除、新来源新增处理，不自动合并身份或迁移动态边。文件编辑期间仍沿用上一完整发布版本。

## 超限与保存

按默认256上限，第257个候选触发现有范围保护；显式配置其他上限时以实际配置为准。当前服务器范围的所有来源撤下并归档，停止处理，避免未能完成扫描时仍使用陈旧来源。不会静默只取限额内的前一批。把超量材料留在 `_staging`，维持候选范围不超限。

超限后再降到限额内，需要重新建立来源、转换和标词；不能直接恢复原来的发布指针。历史原文、来源与已知 usage 保留，但重新处理仍可能产生模型费用。不要把这种恢复和正常失败 digest 不自动重试混为一谈。

原始材料和知识版本不受 scratch 的滚动 24 小时清理。`state` 会随 PDF 与版本增长；可在服务已停止时自行备份整个 `knowledge` 与 `state`，以同时保留原文件、知识/图历史及 checkpoint。scratch 是有限保留的运行记录，不替代知识备份。仓库忽略这两类运行数据，提交代码时不要强制添加原始材料。

0.11.0 首次给已有知识数据库新增 `knowledge_file_audit` 元数据表之前，SQLite backup 在 `state_dir/migration_backups/` 创建一致的原库备份；不覆盖已存在备份，不清库或重建原索引。新表保留验证失败的元数据，原文、来源历史和 checkpoint 不迁移到 scratch。只读 `audit`/进度查看不会触发此迁移。
