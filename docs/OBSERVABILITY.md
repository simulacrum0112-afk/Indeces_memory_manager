# 本机图与运行记录观察

文档基线：0.10.0；2026-10-01 核对。默认静态层及合成浏览器验证的代码检查点见 [CHECKPOINT.md](CHECKPOINT.md)。

智能体名为 **Indeces**。`scratch/` 是人类可访问的普通目录：可以直接用资源管理器/编辑器查看原始日期 JSONL，固定 `README.md` 和 `index.html` 说明查阅方法。Console 的 `logs` 打印此目录和说明路径，不读取认证密钥，不创建运行记录副本。

## 启动与查阅

Console 的 `start` 在独立服务窗口显示 `Indeces read-only observer: http://127.0.0.1:.../.../`。将完整 URL 复制到浏览器地址栏；末尾 `/` 和随机路径都是地址的一部分。该观察服务随 Bot 停止，端口/随机路径下次会改变。观察服务无法启动时服务窗口报告固定错误类型，回复服务继续运行，可另开窗口观察。

独立观察命令不需要 Bot token、OpenAI key 或运行实例锁，可以在 Bot 已运行时使用：

```powershell
cd D:\Indeces
.\.venv\Scripts\python.exe -m indeces observe --config config.local.toml
```

也可在 Windows Console 输入 `observe` 打开独立只读观察窗口，主 Console 继续接收命令；其他平台提示在另一终端运行。观察窗口内 `Ctrl+C` 只关闭该观察服务，结束提示按 Enter 关闭；不会停止 Bot 或启动新 Bot。直接 CLI `observe` 仍在当前终端前台运行。主 Console 的 `quit` 不停止独立服务，服务窗口 Ctrl+C 停机。配置尚未建立时沿用 Console 的配置初始化流程。

页面自动刷新，也可暂停或手动刷新。没有知识/日志时显示真实空状态；读取失败、不完整追加、超限和过期证据有明确提示。观察端不修复、裁剪、迁移或写入运行库。

暂停后仍保留读取失败警示，不把失败快照改成健康；历史关闭时，搜索也不会命中仅历史存在的节点。新观察进程展示本版静态规则，不能据此证明另一个已运行的旧服务已加载新版或 Gateway 在线。

## 图与版本

- 0.10.0 默认静态层，当前回复只按静态 NPMI 扩展与排序；动态层明确标为 shadow 观察历史，有效层也只采用有来源支持的正 NPMI。旧版实际动态接线与当时文档存在偏差，旧事件按旧合同解释。
- 顶部统计聚合完整当前范围，区分有效块/来源版本/词数、正边、单块及单来源支持、NPMI=1 和孤立词。NPMI 是共现关联，不是置信度；稀有词对一次共现也可能得到高分。绘图 500 节点/1000 边上限不等于统计范围。单边详情显示公式分母、两词出现次数、共同出现次数及重算值。
- Console `npmi` 或 `python -m indeces npmi --config config.local.toml` 不读 scratch，只读上述聚合；缺少配置不创建文件。查询达到原 SQLite 限额时报告不可用，不将失败显示为空库。
- 标注词是节点，边来自当前服务器的知识 scope。节点 frequency 是有效来源记录中的出现次数。
- 静态层显示已保存的正 NPMI；原公式取值在 `[-1,1]`，当前策略只保留正边。原始微小正值经既有四位舍入变为零时也不可用；“无可用正权重”不能解释为所有原始分数都非正。动态层是 shadow Hebbian 权重，保留 `η=1`、`λ=.99`，数值可以超过 1。有效层显示本版静态检索所用权重；来源支持不再有效或无可用正静态边时为不可用。
- 拖动节点、平移/缩放、搜索和切换层用于观察结构。布局坐标和线粗只用于显示，不作为新的语义距离、检索分数或科学指标。
- 点选边查看当前静态/动态权重、上下文门控材料、来源版本，以及不可变事件记录中的种子、衰减、强化前后值和触发查询。时间线来自 SQLite 图事件审计，按事件变化记录绘制，不插值推断未记录的学习。
- 已无有效来源的动态边仅属于保留历史；页面不能将其重新激活。点选来源可查看保存的版本原文、digest、标签、块与 published/desired 状态。新版本未 ready 时，发布目录继续显示旧完整版本。
- PDF 来源详情另显示转换稿、原 PDF/Markdown digest、物理页区间、提取警告和归档字节 hash 核验状态；最多读取16 MiB归档PDF，仅返回hash与状态，超限/缺失/截断明确标为未核验。未重建公式/表格/图像，不把字节一致性当成纸面科学内容验证。

当前每个具有直接字面命中的检索才产生治理周期，衰减以检索次数计。**没有新增随聊天模型标词、聊天入库或逐轮语义权重调整。** 可视化只是现有机制的观察入口；真实长期召回效果仍需用户的知识与代表性对话试验，不能由图形或单轮回答证明。

## Scratch 与核验

页面列出最近 trace，展示可核验事件、冻结召回材料/版本、图变化、字面引用和调用 token/时间记录；原始 JSON 可展开。生成文字与实际送达文字属于不同事件。

读取同一文件的冻结字节后校验外层/hash/checkpoint；完整性检查失败时整文件暂不可核验，不把正在追加的前缀当作完整文件。Windows 用按规范目录路径命名的短 mutex 串行冻结读取和清理替换/删除，字节读取后立刻释放，校验和 HTTP 发送不占锁；保留原 `os.replace` 原子替换与失败处理。reader 允许删除共享，但本机试验表明仅共享还不足以保障 `MoveFileEx` 替换。mutex 的跨进程行为依据 [Microsoft CreateMutexW](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexw)，实际等待/替换与中断恢复另有合成测试。reader 最多等待 2 秒、writer 最多等待 10 秒；文件 I/O 仍不是硬抢占。页面对保留的材料、图算术和字面引用做局部一致性检查，**不检查完整调用/回答生命周期**。完整检查仍使用：

```powershell
.\.venv\Scripts\python.exe -m indeces scratch --config config.local.toml
```

`retention_partial` 表示 trace 的部分记录已跨窗口；页面截断、依赖缺失和尚未检查的生命周期均不是“完整通过”。材料召回、字面标记和语义支持不同，语义支持未自动评估；本地 hash 无外部锚点。

页面按查询时 UTC 过滤最近 24 小时，即使 Bot 停服而物理文件尚未清理也不返回已到期的 scratch 原文。磁盘清理仍只由现有启动/每 60 秒维护负责；观察命令不清理。固定说明页不含私有运行数据，浏览器不持久存储/缓存数据，后端不生成导出副本。SQLite 知识版本、消息/checkpoint、图事件审计按既有持久策略保留，**不受 scratch 的 24 小时限制**，图时间线可显示更早的已记录变化。

## 读取范围与隔离

观察服务只绑定 `127.0.0.1`，使用临时端口和随机路径；只允许限定 GET 路由，检查 Host、Origin 和浏览器请求来源，禁止跨源与缓存，所有资源本地提供。它没有修改图/配置/知识的接口，没有模型或 Discord 操作。不要把含随机路径的 URL 分享给他人；本机有访问权限的进程仍属于信任边界。

HTTP 请求在独立线程中串行处理，与 Runtime 及模型请求槽分离；SQLite 用只读短事务、0.25 秒锁等待与 2 秒 VM 协作检查。文件 I/O、JSON 与 Python 排序仍非操作系统硬抢占，不能声称任意数据规模下有严格响应时限。

为保持小型服务，当前显示上限为 500 节点/1000 边/图 2 MiB；单边历史最多 100 次变化、扫描最近 1000 个审计事件/显示 2 MiB；来源原文最多 256 KiB 字符且不超过 512 KiB UTF-8、512 块、合计 1 MiB。scratch 扫描最多 8 个日期文件，单文件 32 MiB、总计 64 MiB、10000 条记录，列表最多 100 trace；单 trace 最多 1000 条/4 MiB。HTTP 响应上限 8 MiB。省略明确显示；超限文件不以未核验前缀替代，完整原始记录仍可在其保留窗口内用 Console 检查。扩大知识规模前应实测性能并调整设计。
