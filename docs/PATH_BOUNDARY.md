# 知识库路径边界与来源隔离

0.12.5；2026-10-02（用户时区）。本机知识材料的唯一入口是 `D:\Indeces\knowledge`。不得把其他资料目录配置为知识库，或在其中生成知识库管理结构。原始资料不由程序移动、改名、删除或整理。

## 已确认的代码缺口

旧加载器允许任意 `knowledge_dir`；目录入口会在所配置目录建立 `_staging` 和 `.indeces/README.md`。旧启动链捕获目录准备错误后继续入库，使安全拒绝不能阻断扫描。配置解析过早调用 `resolve()`，会丢失链接或 junction 的原始路径。

旧数据库把知识来源绑定到服务器范围与相对文件名，没有根目录身份。更换目录后，旧已发布来源可能沿用；首次完整扫描以前也可能被回复检索。仅修改配置不足以证明旧来源已隔离。

## 新边界

加载器要求知识库是项目配置文件旁的 `knowledge` 子目录；本机项目配置在 `D:\Indeces`。跨目录的绝对路径、相对逃逸和任意其他目录名均拒绝。便携安装仍以所选项目配置所在目录为项目位置，不能将此合同描述成所有机器都硬编码同一盘符。

配置、知识库、state、scratch 的原始路径和祖先在解析前检查，再检查规范化路径与同步根身份；Windows 8.3 短名不能隐藏被禁止的目录。OneDrive 名称路径、其环境变量指定的同步根，以及符号链接、junction、reparse point 均拒绝。启动、重试、知识扫描、目录说明、凭据向导、观察与底层数据库/日志/租约入口均应用相应校验。配置根目录拒绝发生在启动副作用前；内部目录和文件在对应访问前校验，不代表整个流程具有零副作用的原子预检。目录安全错误不能继续入库。普通说明文件的权限错误仍可按原合同报告，前提是根路径校验通过。

知识来源新增服务器范围到根目录的持久绑定。旧无绑定来源须在允许的当前目录找到同路径、同字节 digest 的文件，才能沿用。不存在、内容不同、保留区文件及孤儿来源在开放 Gateway 前撤下并归档；已记录的根目录变化不继承旧来源，即使相对文件名和字节相同。迁移前保存一致 SQLite 备份，原文、PDF 原字节、标词及累计计量不删除。未知请求用量及未知服务器的材料另保留持久 digest 禁发记录，不能因文件消失后重新出现而获得一份新预算。

施工中间版的同根目录旧库也按服务器范围的 v2 迁移标记检查；缺表或缺标记都先备份，再补齐禁发记录，不能因根目录相同跳过。普通撤下与版本替换在覆盖旧错误前保存禁发 digest；显式 retry 同样遵守禁发记录和明确的未知用量错误。旧版本已覆盖错误而无法确认用量的历史归档，保守标为 `legacy_archived_usage_unverified`，以独立回执区别于确认的未知请求；相同范围、相对路径与 digest 不自动重放。当前完整发布版本和已完成替换不因此清空，文件内容改变仍按原版本合同处理。无服务器归属的来源只在有当前范围的指针、hold、审计或历史图归属证据时关联，不凭文件名猜归属。

字节匹配只确认当前材料身份，不证明过去从哪个目录读入，也不验证 PDF 提取语义。校验是协作式文件系统检查，不是防止恶意并发替换的操作系统原子目录租约。

## 后果与调查限制

误配置后可能留下管理说明、原文/PDF 的 SQLite 副本、转换稿、标词及计量；标词和回复阶段可能发送材料文本。撤下来源不会消除历史已送达回复或 checkpoint 摘要，scratch 则仍按原 24 小时合同处理。不能把目录修复说成外部已发送内容被撤回，也不能自动删除历史来掩盖事故。

本次有限追溯扫描修复前 main 的 30 个可达提交，以及六个相关施工/文献编辑聊天共 25 个 turn。没有发现被报告文献目录的移动/删除操作；已定位的知识目录建设命令成功断言了正确的项目知识库路径。当前与历史生产知识代码没有移动、删除原始 PDF 的路径。由此不能认定文件缺失由已审计的聊天、Indeces 或 OneDrive 同步中的哪一方造成；历史子任务、其他聊天和同步删除历史未完整覆盖。

本轮不修改被报告的外部目录、不恢复或搬运已有备份、不启停真实服务，不在活动入库任务上应用数据库迁移。离线证据与准确交付状态见 [CHECKPOINT.md](CHECKPOINT.md)。正在运行的 Console 必须自然结束当前任务，由用户显式重开后加载最终版；源码版本号相同也不证明施工中启动的实例已加载最终文件。
