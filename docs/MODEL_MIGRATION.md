# GPT-6.1 Sol migration (0.14.0)

The user explicitly requested `gpt-6.1-sol`, medium reasoning, with every other
setting unchanged. This replaces the previous single-model baseline; it does
not introduce routing, fallback models or extra requests.

| Parameter | Original → proposed | Classification |
|---|---|---|
| `adapter.model` | `gpt-6-luna` → `gpt-6.1-sol` | Task-essential, explicitly requested |
| `adapter.budgets.label.reasoning` | `low` → `medium` | Task-essential, explicitly requested |
| `adapter.budgets.summary.reasoning` | `low` → `medium` | Task-essential, explicitly requested |
| `adapter.budgets.reply.reasoning` | `low` → `medium` | Task-essential, explicitly requested |
| `adapter.verbosity` | `high` → `high` | Unchanged |

| Summary input/output/seconds | `16384/2048/20` → same | Unchanged |
| Reply input/output/seconds | `16384/2048/45` → same | Unchanged |
| Global/version/maintenance resource caps, endpoint, authentication, request slot, chunks, prompts, schema, graph and retention rules | Original values → same | Unchanged |

These are LLM settings, not changes to a scientific potential energy surface
or numerical calculation. The [official model documentation](https://developers.openai.com/api/docs/models/gpt-6.1-sol)
supports `medium`, Responses and structured outputs. It does not support
`none` or `minimal`; unsupported settings fail local validation rather than
being silently rewritten. Explicit supported reasoning values remain explicit.
The existing context/output validation bounds still fit the documented model.

The config template, omitted reasoning default, model admission, adapter
description and bounded-maintenance baseline use the new settings. Input
counting and generation share the same actual model/effort, and scratch still
records the request and budget. There is no token/deadline increase to compensate
for a model change. Runtime and visible output under these caps require live
validation; offline success does not establish response quality or latency.

Local configuration migration must acquire the existing state lease, verify
the file did not change, save an exclusive byte-for-byte backup and replace
only the four requested values. All remaining parsed fields and untouched
text are checked for equality. An active lease blocks the write. The loader
does not silently migrate old model IDs, and already loaded processes do not
become current simply because the files or package version changed.

No knowledge, source, checkpoint, usage, failed call, graph or scratch history
is migrated, cleared or relabelled. Existing labels remain their original
completed versions; they are not claimed to have been generated by Sol. New
calls record their actual model/effort under the existing receipt contract.
Unknown-usage and resource gates stay in force. This request does not launch
maintenance, replay an old grant, stop/start Discord or perform a live model call.
